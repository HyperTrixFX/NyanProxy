# 项目概述与架构

## 技术栈

- **语言 / 平台**：Java 21
- **框架**：Spring Boot 4.1.1
- **持久层**：Spring Data JPA + MySQL（`ddl-auto=update`）
- **缓存**：Spring Data Redis（Lettuce）
- **网络（代理）**：Netty（NioIoHandler / MultiThreadIoEventLoopGroup）
- **其他**：Lombok、fastjson2、OkHttp、Quartz、Spring Statemachine、spring-boot-starter-mail / websocket / actuator、`io.github.kloping.qqbot`（QQ 机器人）

## 关键概念

### UID 与 Minecraft UUID

- **NyanID UID**：32 位十六进制字符串（`utilset.GenerateUUID`，去除连字符），是 `Accounts.uid`。
- **Minecraft UUID**：Yggdrasil / Mojang 的玩家 UUID（`Yggdrasil.uuid` 存储带连字符的 36 位）。
- 二者通过 `Yggdrasil.nyanuid` / `Yggdrasil.uuid` 建立映射；`Accounts.bind` 也可作为绑定来源。

### 认证链路

1. 用户登录拿到 RSA 加密的 `accessToken`（对应 `UserDevices.Token`）。
2. Web API 通过 `Authorization: Bearer <加密token>` 头传递，服务端用 `utilset.decrypt(..., privateKey)` 解密出原始 token，再查 `UserDevicesRepository.findUidByToken` 得到 uid。
3. 某些端点还会经过 `AuthenticateCheck` 拦截器校验 `Event` 头与 HTTP 方法是否匹配。

### 权限节点

见 [08-权限与封禁系统](./08-权限与封禁系统.md)。授权按节点字符串匹配，支持 `*` 根节点与 `prefix.*` 通配。

### 封禁

见 [08-权限与封禁系统](./08-权限与封禁系统.md)。游戏封禁区分「Yggdrasil 玩家 → 封 NyanID UID」「正版玩家 → 封 UUID」，支持过期自动解封。

### QQ 机器人（Qbot）

见 [10-QQ机器人](./10-QQ机器人.md)。基于 `io.github.kloping.qqbot`，支持固定指令、NyanID 邮箱绑定、只读查询、长期记忆、小游戏与 AI 聊天；命令层由 `QbotCommandService` 统一路由。

### AI 服务

见 [11-AI服务](./11-AI服务.md)。`AIServices` 支持 Ollama / DeepSeek 后端，带多轮只读工具调用、Redis 临时会话、MySQL 长期记忆与防注入提示词，供 `/api/v6/romyuai/chat` 与 Qbot 共用。

### 用户管理与工单

见 [12-用户管理与工单系统](./12-用户管理与工单系统.md)。V3 管理端提供用户列表/详情/编辑/启停/封禁/解封/权限（`nyanid.admin.user`）与工单查看/处理（`nyanid.admin.ticket`）；V1 提供工单自助提交与查询。
